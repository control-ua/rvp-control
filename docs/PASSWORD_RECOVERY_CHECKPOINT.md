# Восстановление пароля — сохранённый этап

Работа приостановлена по просьбе владельца. Изменения формы входа и восстановления НЕ опубликованы. Рабочая система: кабинет rpv-portal v1, бот smart-api v120.

Подготовлены:
- Кнопка «Забули пароль?» и форма запроса письма через resetPasswordForEmail.
- Отдельная страница нового пароля по recovery callback: проверка сессии, очистка токенов из URL, обработка истёкшей ссылки, повтор пароля, минимум 12 символов.
- Изоляция восстановления от обычного входа и Telegram-кабинетов; защита от двойного обмена одноразового токена в React StrictMode.
- Четыре теста парсинга callback, подкаталога GitHub Pages и валидации пароля.

Проверено: четыре теста прошли. TypeScript и production build завершились успешно. Браузерная проверка новых экранов и фактическая доставка письма ещё не выполнены.

Блокирующий шаг: проверить Supabase Auth URL Configuration. Адрес возврата должен разрешать https://control-ua.github.io/rvp-control/?auth=recovery; Site URL должен быть рабочим адресом портала. Подключённые MCP-инструменты не предоставляют редактирования Auth config. В браузере вход Supabase через GitHub дошёл до подтверждения устройства кодом из почты. Ввод кода был отменён; авторизация в панели Supabase не подтверждена. Не повторять запрос кода без возобновления пользователем.

Продолжение:
1. Просмотреть текущий код, завершить TypeScript/build и браузерную проверку формы и недействительной ссылки.
2. При необходимости добавить тесты жизненного цикла recovery (успех и ошибка обмена, отсутствие токенов) без реальных паролей/аккаунтов.
3. Войти в Supabase с владельцем через защищённую форму, проверить/настроить адрес возврата, сохранив существующие разрешённые адреса.
4. Выпустить изменения через GitHub и проверить опубликованную форму.
5. Владелец сам запрашивает письмо и задаёт новый пароль. Никакие пароли, OTP или recovery-ссылки не передавать в чат, не читать через почтовые инструменты и не сохранять в отчётах.
